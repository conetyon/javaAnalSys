# 变更：添加代码解释功能（关键行标注 + AI 按需解释）

## 为什么需要

当前系统返回的代码片段对学习者来说是"孤零零"的，缺乏上下文解释。用户反馈：

1. 不知道代码中哪些行是关键的、与知识点直接相关的
2. 对于复杂概念，希望有智能解释而非自己逐行阅读
3. 有时想针对特定代码提问

## 核心设计

采用**混合方案**，分两个层次提升用户体验：

### 层次 1：关键行标注（默认展示，零成本）

- 实时计算关键行（基于已有 AST 分析能力）
- 前端高亮显示关键代码行
- **配额耗尽后的降级方案**：用户仍可通过标注获得基础帮助

### 层次 2：AI 按需解释（用户触发，成本可控）

- 用户点击"AI 解释"时才调用 LLM
- 支持流式输出（SSE），提升交互体验
- 支持多轮问答，上下文记忆
- **智能补救**：如果代码片段不理想，AI 会自动生成更合适的示例
- **配额限制**：非管理员用户有每日请求限额

## 什么变更

### 后端变更

- **ADDED** `HighlightService`：实时计算关键行（不修改数据库）
- **ADDED** `ExplainService`：AI 代码解释服务，接入 LLM API
- **ADDED** `LLMClient`：封装 LLM API 调用（OpenAI 兼容接口）
- **ADDED** `/api/explain` 和 `/api/explain/chat` 端点（SSE 流式响应）
- **ADDED** `/api/user/quota` 端点：查询配额
- **ADDED** `user_quotas` 表：用户配额管理
- **ADDED** `explain_logs` 表：请求日志（审计）

### 前端变更

- **MODIFIED** `CodeBlock` 组件：支持行高亮 (`highlightLines` prop)
- **ADDED** `CodeExplainer` 组件：AI 解释面板 + 多轮问答
- **ADDED** `QuotaIndicator` 组件：显示剩余配额

### 配置变更

- **ADDED** `config/llm.yaml`：LLM 服务配置
- **ADDED** 环境变量 `LLM_API_KEY`

## 风险评估

| 风险 | 缓解措施 |
|------|----------|
| LLM API 不可用 | 关键行标注不依赖 API，基础体验不受影响 |
| 配额耗尽 | 1) 关键行标注仍可用；2) 前端提示剩余配额 |
| 代码片段不理想 | AI 自动生成更合适的示例代码 |
| API 成本超支 | 配额限制 + 日志审计 |

## 成功标准

1. 关键行标注：匹配结果默认显示高亮行
2. AI 解释：P95 响应时间 < 3 秒（首 token）
3. 配额系统：准确限制非管理员用户请求次数
4. 智能补救：AI 能识别不理想片段并生成更好示例
